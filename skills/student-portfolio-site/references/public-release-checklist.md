# Public Release Checklist

Use this before a portfolio is shared publicly, deployed, turned into a demo repository, or exported as a public showcase. Review does not authorize publication; obtain the student's explicit instruction before an external write or deployment.

## Content and privacy

- Confirm every phone number, email address, social handle, school record, portrait, and resume download is intentionally public.
- Review screenshots, PDFs, image metadata, filenames, hidden notes, private links, and repository history for personal or employer-sensitive information.
- Replace confidential product screens, customer data, internal metrics, credentials, and unpublished materials with authorized abstractions or remove them.
- Clearly distinguish individual contribution, team contribution, prototype, and production work.

## Repository and links

- Check that `.env`, keys, tokens, private endpoints, draft files, and large source assets are excluded from the public repository.
- Verify changed routes, download links, contact actions, project links, and external destinations.
- Use only assets, fonts, images, and icons that are authorized for public use. Do not ship copied reference-brand assets.

## Usability, access, and performance

- Check desktop and narrow mobile layouts, visible keyboard focus, heading order, meaningful image alternatives, sufficient contrast, and reduced-motion behavior.
- Compress or resize oversized images; avoid loading nonessential media before the first screen is useful.
- Confirm the title, description, and preview metadata describe the student truthfully.

## Final disclosure

- State what was checked, what remains unverified, and which facts or placeholders still need the student's confirmation.
